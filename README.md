# 跨馆短线的赶场风险与转场席位

半日联线的场次、换乘观察和接驳席位台账。 `data/` 中的记录均为虚构业务数据。

使用 Python 3.11.2。资料核验与排期计算仅依赖标准库。

在仓库根目录核验资料格式、键值与关联记录。

```bash
python3 -m unittest discover -s tests -v
```

## 排期工具

`shuttle/` 把资料变成值班员可以照办的结论：哪些家庭按现有班次排得下、改场次和留接驳席各要付什么代价、通知生效后哪些承诺还能保留。所有命令只读 `data/`，不回写来源记录。

```bash
# 当前时点的整组安排、席位占用与未获保证的自换乘
python3 -m shuttle brief --at 2026-12-06T10:30:00+08:00

# 单个家庭：改场次 vs 留接驳席，连同同批家庭和可能被挤占的恢复席位
python3 -m shuttle compare F3 --at 2026-12-06T10:30:00+08:00

# 停开通知生效后，草稿运行单里的家庭按 保留 / 需确认 / 来不及 分桶
python3 -m shuttle duty --at 2026-12-06T10:30:00+08:00 \
  --prepared-at 2026-12-06T08:00:00+08:00

# 复盘：批准时依据的风险证据、席位承诺与事后结果
python3 -m shuttle review --at 2026-12-06T10:30:00+08:00
```

## 计算口径

这些是工具里写死的判断，不是可调参数。

**以整趟观测为单位，不相乘各段。** 同一观察日里，两个场馆的参观段和接驳段是一起记下来的，共享当天的天气与客流。各段偶尔快、偶尔慢并不独立，把各段成功率相乘会凭空造出信心。每一趟观测从头到尾走一遍，只计一次。

**没有观测的段不进证据集。** 一个方案只在它实际乘坐的接驳段当天都有记录时才算有证据；靠步行的走廊不需要记录。缺记录的日子被排除，而不是用别处的平均补上，所以证据条数会随方案变化并如实标出。

**步行段给区间，不给点估计。** 登记的无车步行时间没有用时观测。乐观值用登记分钟，悲观值加上同一天同一走廊接驳段的最坏正偏差——同走廊相邻段一起变慢，所以那天车晚，走路也晚。低于家庭底线的是悲观值，只凭乐观值不能放行。

**三类记录分开。** 确知迟到（到得晚、或没赶上车）、旅程没走完（班次停开且没有步行可补）、观测未结束（censored，既不算完成也不算失败）分别记数。全部按时跑完的观测日是真“零迟到”证据，算完成，不算 censored。

**场次是固定窗口。** 参观在场次 `ends` 加当天超出时间结束；晚入场只缩短参观，不延长窗口。签到上限含该分钟（`到达 <= last_checkin`）。

**底线看基准层。** `family_route` 的 floor 是按正常运行线路约定的完成率，用 `normal` 观测层判定。雨天是另一层，由 `activation` 的触发条件驱动，单独给出，不并入底线。

**席位按整户计**，一票同行，从不拆家庭。`capacity` 是人头，已对客承诺的 `locked` 席位一直占座，即使家庭改线也不自动释放；释放只能由值班员与家庭确认后显式进行。

**相邻段一起变慢。** 同一走廊的触发同时影响多个家庭时，一车席位不能同时作为多个并发影响的保证。互斥组里同一截止的两个触发无法区分是哪一种，不能共用同一应急席。

**通知按生效时刻。** 车开停复核看 `effective_at`，收件顺序不改变结论。运行单在确认前遇到生效通知即作废，不能拿按旧时刻算出的结果占座；家庭已经收到的安排优先保留，能不能继续、要不要向家庭确认、来不来得及更换，分别交给值班员。

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `model.py` | 解析资料表、时钟运算、按生效时刻取通知状态 |
| `risk.py` | 单家庭单方案的整趟完成率、支持区间与证据分桶 |
| `seats.py` | 整户席位台账、承诺占用、互斥/并发触发 |
| `assign.py` | 在底线与席位约束下整组选方案，比较改场次与留席 |
| `compare.py` | 改场次 vs 留接驳席的并列比较与失败原因定位 |
| `duty.py` | 通知生效后的运行单作废判定与家庭分桶 |
| `plan.py` | 汇总成值班员看的时点简报 |
| `retro.py` | 批准依据与事后结果的对照记录 |

各表来源及字段约定见 [资料约定](data-contract.md)。
